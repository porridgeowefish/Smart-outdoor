# Acceptance Criteria

Status: draft
Owner: project maintainer
Last reviewed: 2026-06-14
Source of truth: acceptance checklist for Iteration 09.

- [US-09.1] 用户在选择卡选定或输入出发城市后，系统能记住该位置。
- [US-09.1] 后续推荐只出现该城市附近的线路，不再出现明显跨地域的线路。
- [US-09.2] 用户表达含糊需求时，系统一次让用户多选的“含义”不超过 4 种。
- [US-09.2] 每道选择题给出 2-4 个选项。
- [US-09.2] 系统已经问过的需求不重复追问。
- [US-09.3] “轻松 / 刺激”类需求系统按用户能力理解，不要求用户从标签里挑。
- [US-09.3] 路面 / 导航 / 安全 / 风景类需求，系统让用户从标准标签里挑选。
- [US-09.3] 标签选择分批进行，一次不让用户挑选过多。
- [US-09.3] 系统写入偏好前必须先经用户确认。
- [US-09.4] 用户的风景偏好、补给需求、路况容忍度和安全优先级都被准确记录。
- [US-09.5] 智能召回失败或不稳定时，用户仍能用基本选择卡表达需求。
- [US-09.5] 切换底层智能能力不影响用户的操作流程。
- [US-09.6] 系统向用户提的问题简短（不超过 100 字）。
- [US-09.6] 可选项都来自既定标签库，不会被凭空生成。
- [US-09.6] 系统不把召回说明展示成确定事实或安全承诺。

## 不验收为完成

- 只建了知识库但没接入选择卡的选项。
- 智能召回结果绕过用户确认，直接影响推荐或写入。
- 没有测试的智能召回实现。
- 把近期路况、天气、安全状态当作标签知识库的事实输出。
- 引入向量数据库、线路重排或多阶段规划框架。
- 修复召回的排序 / 过滤（召回忽略风景 / 补给 / 路况 / 安全是后续迭代的待修项，不阻塞本轮验收）。
