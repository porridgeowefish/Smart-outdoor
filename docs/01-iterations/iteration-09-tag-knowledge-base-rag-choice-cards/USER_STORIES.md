# User Stories

Status: draft
Owner: project maintainer
Last reviewed: 2026-06-14
Source of truth: this iteration plus implementation tests after this slice lands.

## US-09.1 拿到精确的出发地理位置

作为用户，我希望在选择卡里选定或输入出发城市后，系统能把它转换成带经纬度的结构化位置，以便后续推荐只给我附近可达的线路。

## US-09.2 多选“简单”的具体含义

作为用户，当我说“希望线路比较简单”时，我希望系统让我多选“简单”具体指哪几种（比如体力轻松、路面好走、容易导航），以便推荐贴合我的真实意思，而不是一次堆给我几十个标签。

## US-09.3 区分主观强度与客观需求

作为用户，我希望“轻松 / 刺激”这类需求按我的个人能力来理解，而路面、导航、安全、风景这类需求让我从标准标签里挑选，以便系统能分清“相对我的能力”和“线路本身的客观特征”。

## US-09.4 记录偏好的完整维度

作为用户，我希望我的风景偏好、补给需求、路况容忍度和安全优先级都能被准确记录，以便推荐不漏掉这些需求。

## US-09.5 召回不稳时仍能表达需求

作为用户，我希望在系统智能召回不稳定时，仍能用基本选择卡把需求说清楚，以便流程不被技术故障卡住。

## US-09.6 提问简短、选项可信

作为用户，我希望系统向我提的问题简短清楚、可选项都来自既定的标准标签库，以便我快速准确地表达需求。
