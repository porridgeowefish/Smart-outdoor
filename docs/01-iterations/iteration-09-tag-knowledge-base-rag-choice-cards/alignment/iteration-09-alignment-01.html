1. 本次要判断什么

Iteration 09 接在 Iteration 08 的选择式需求收敛之后。它不替代选择卡，而是让选择卡的选项来源更聪明、更可解释。

用户原话想玩雪，但不要太危险
粗抽取目标、时间、出发地等基础字段
标签召回雪景、安全、成熟路线、冰雪路
选择卡让用户确认偏好和避开项

2. RAG 的角色边界

允许不允许
召回可能相关的标签、风险维度和选项方向。绕过用户确认，直接写入高可信 user_choice 字段。
为选择卡提供可解释 option。生成近期路况、天气、安全状态等事实断言。
召回不足时降级到基础选择卡。因为向量相似就扩大推荐范围或做最终推荐。

3. 标签知识库形态

候选字段：tag、category、description、positive_phrases、negative_phrases。

内存常量最快、最容易测试，不需要迁移；更新需要发版。
本地 JSON/YAML仍然简单，便于维护和审阅；需要加载和校验。
数据库表便于后台维护；会增加迁移和管理边界。
混合方案内置基础标签，未来再叠加运营配置。

5. 接口与数据边界

默认复用 Iteration 08 的 choice_request，让 RAG 结果成为选项来源，而不是新增一组用户入口。

{
  "field": "preference_tags",
  "options": [
    {
      "label": "成熟路线看雪为主",
      "value": "managed_snow_view",
      "source": { "type": "tag_retrieval", "tag": "managed_snow_view" }
    }
  ]
}

6. 测试与验收口径

成功路径自然表达召回标签，生成选择卡，提交后写入标准字段。
失败路径无命中、非法 value、旧 choice_request、provider 失败。
权限不能提交或恢复他人 TripPlan 的选择请求。
降级召回不可用时回到 Iteration 08 基础选择卡。
