# Acceptance Criteria

Status: active
Owner: project maintainer
Last reviewed: 2026-06-14
Source of truth: acceptance checklist for Iteration 08.

## US-08.1 同一会话内选择式需求收敛

- [US-08.1] 用户输入自然语言后，系统可以返回一组待确认选择卡，而不是只显示文字追问。
- [US-08.1] 用户在同一个对话中可以连续完成多轮选择，不需要新开会话。
- [US-08.1] 一轮多个问题逐步呈现，不一次性全部铺开。
- [US-08.1] 每次选择后，已确认条件展示会更新。
- [US-08.1] 条件足够后，系统生成最多 3 条候选线路。

## US-08.2 统一的选择式提问

- [US-08.2] 系统需要用户补充信息时，用统一格式的选择卡提问。
- [US-08.2] 选择卡支持单选、多选和文字补充输入。
- [US-08.2] 每道选择题给出 2-4 个选项；文字题可不提供选项。
- [US-08.2] 一次提问最多 3 个问题，但逐步呈现。
- [US-08.2] 允许自定义补充时，系统记录用户真实输入，不把“其它”当成业务值。

## US-08.3 多次选择后生成推荐

- [US-08.3] 系统在每次用户选择后判断需求是否足够。
- [US-08.3] 需求足够时系统自动生成推荐。
- [US-08.3] 涉及雪、野路、亲子等风险场景时，系统必须先确认路况或安全偏好，才生成推荐。
- [US-08.3] 信息不足时系统不假装已理解，不生成强结论推荐。
- [US-08.3] 推荐仍只基于数据库线路、API 证据和带 URL 的外部证据。

## US-08.4 历史会话恢复选择状态

- [US-08.4] 重新打开历史对话时，之前未完成的选择卡仍可继续提交。
- [US-08.4] 已提交的选择记录展示为可读的选择摘要。
- [US-08.4] 重新打开对话时，只有最近一条未完成的选择卡恢复为可交互。

## US-08.5 推荐后的追问与修改

- [US-08.5] 推荐生成后，用户仍可继续追问或要求解释。
- [US-08.5] 用户可以修改条件（例如更轻松、更近、不要冰雪路）。
- [US-08.5] 修改关键条件后，系统可以重新收敛或重新推荐。

## US-08.6 短输入、口语输入和冲突输入

- [US-08.6] 短输入（例如“周末想出去走走”）会触发选择卡。
- [US-08.6] 冲突输入（例如“轻松但要高强度爬升”）会触发澄清，而不是直接猜测。
- [US-08.6] 系统不输出“放心去”“一定适合”“绝对安全”等禁用话术。

## 通用

- 用户的显式选择优先于系统从自然语言中抽取的倾向。
- 系统抽取的倾向不能静默覆盖用户已确认的选择。
- 已关闭的规划不能继续发消息或提交选择。
